Esta presentación es para audiencia mixta: devs y managers en la misma sala, todos con poco tiempo. El objetivo: que en 10 minutos todos entiendan qué hace Kiro Crew y quieran probar 15 minutos esta semana. No empieces con "hoy voy a hablar de..." — empieza directo con el número del slide 1.

Interest

El problema no es que los devs sean lentos — es que el contexto se pierde entre herramientas.

  • Un dev pasa ~35% de su tiempo buscando contexto que ya existe en otro lugar
  • Cada cambio de herramienta (IDE → Slack → doc → IDE) cuesta ~23 min de reconcentración
  • Un manager espera una feature mientras el dev reconstruye contexto que el manager ya tiene
Aquí hablas con ambas audiencias al mismo tiempo. Al dev: "Saben de qué hablo — el rabbit hole de leer 8 archivos antes de tocar uno." Al manager: "Y ese tiempo invisible es exactamente por qué el sprint se extiende." Pausa un segundo entre los dos. Que cada uno sienta que les hablaste directo. Si tienes datos propios del equipo, úsalos aquí en lugar de los porcentajes genéricos.
Desire — el sistema

Kiro Crew es un agente que recuerda tu codebase, aprende tus patrones y hace trabajo completo en tu nombre.

  • Memory — sabe qué hay en tu repo, qué decidiste antes, qué patrones usas
  • Skills — protocolos especializados que le das para tareas específicas
  • Agents — puede delegar partes del trabajo a sub-agentes en paralelo
La analogía que funciona para ambas audiencias: "Piensen en un desarrollador senior que siempre está disponible, ya leyó todo el codebase, y no se cansa de los tasks repetitivos. Eso es Kiro Crew." Para el dev: es el compañero que sabe todo el contexto. Para el manager: es velocidad sin más headcount. No profundices en cómo funciona internamente — eso viene en el siguiente slide con el caso real.
Desire — en acción

Este framework fue construido con Kiro Crew en una sesión — 7 skills, 6 PRs, y este .pptx generado automáticamente.

  • Prompt: "crea un framework de presentaciones para audiencias técnicas y no-técnicas"
  • Resultado: 7 skills, workflow ejecutable, 3 ejemplos end-to-end, script Python de exportación
  • Entrega: cada PR fue creado, revisado y mergeado dentro de la misma sesión
Este es el meta-momento: "Lo que están viendo ahora — este deck — fue generado por el pipeline que construimos con Kiro Crew." Si la audiencia es técnica: esto les va a gustar. Si no es técnica: "El mismo sistema que les explico fue el que hizo el trabajo." Deja que eso aterrice un segundo. Es el momento más fuerte del deck.
Desire — mapa de conceptos

Kiro Crew tiene cinco building blocks — empiezas con uno y agregas los demás cuando los necesitas.

  • Skills — protocolos para tareas específicas (primer paso, 5 min para configurar)
  • Workflows — pipelines multi-fase reiniciables, visibles en el dashboard
  • Crons — cualquier tarea recurrente automatizada con un script
No intentes explicar los 5 en detalle. Di: "Estos son los 3 que vas a usar la primera semana." Luego: "Hay dos más — Artifacts y Subagents — los vas a necesitar cuando tus tareas crezcan. No te preocupes por ellos hoy." Eso reduce la carga cognitiva sin quitar información. Si alguien pregunta por los otros dos: "Con gusto te los muestro después — son para cuando ya tengas los primeros tres funcionando."
Action

Puedes empezar hoy — el primer resultado útil toma menos de 15 minutos.

  • Si eres dev: abre un proyecto, describe una tarea en lenguaje natural, mira qué hace Kiro
  • Si lideras un equipo: pide a un dev que lo pruebe esta semana y mide el tiempo — compara con el promedio anterior
  • El único requisito: tener un proyecto con código existente
